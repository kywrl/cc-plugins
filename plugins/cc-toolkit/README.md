# cc-toolkit

实时监控 Claude Code 的**输出速度 (tok/s)**，并把**纯解码速度**和整轮速度分开报。

- 每轮回复结束后显示本轮步数 / 每秒输出 / 缓存命中三个读数（Stop hook，自动生效）
- 零 npm 依赖、纯本地计算、不联网、无斜杠命令、无 CLI

```
12 步 | 每秒输出 164 tok/s | 缓存命中 92%
```

**三格位置固定**：某一项这一轮真的测不出来时显示 `—`，而不是整段消失 ——
否则「这行有几个数」会在每轮之间跳变，得先数一遍才知道少了什么。

**为什么不是一个数字**：一轮耗时里混着 prefill（读 prompt）和 decode（写回答）。
合成一个 tok/s 时，prompt 越长读数越低，会被误读成"模型变慢"。所以「每秒输出」用的是
扣掉首段等待之后的纯解码速度。本机实测整轮中位 32–71 tok/s，但纯解码中位 164 tok/s
—— 差的正是首段等待那几秒。

**「一轮」的定义**：从**你按下回车**到这一次回复结束。中间模型可能走几十上百**步**
（每步 = 一次模型生成及其触发的工具执行），这些都属于同一轮 —— 三个读数都是在这一整轮上
算出来的，不是某一步的。

## 快速开始

安装后让 Claude 回一句有实质内容的话即可，**不需要任何额外配置**。
回复结束后应看到 `N 步 | 每秒输出 … tok/s | 缓存命中 …%`；没看到就把
`CC_TOOLKIT_VERBOSE=1` 打开，它会说明为什么静默退出。

## 配置

| 想要的效果 | 怎么做 |
| --- | --- |
| 开箱即用的每轮读数 | 安装后自动生效，无需配置 |
| 每轮只看其中几项 | `settings.json` → `env.CC_TOOLKIT_SHOW = "steps,cache"` |
| 关掉截断/重试提示 | `settings.json` → `env.CC_TOOLKIT_ALERTS = "0"` |
| 调整显示下限 | `settings.json` → `env.CC_TOOLKIT_MIN_TOKENS = "50"` |
| 临时关掉 | `settings.json` → `env.CC_TOOLKIT_DISABLE = "1"` |

**完整的安装方法、精度说明与故障排查，见
[仓库根 README](../../README.md)。**

## 数据来源

`~/.claude/projects/<项目目录名>/<session-id>.jsonl` —— Claude Code 自己写的会话日志。
除了每轮的 `usage`（token 数、缓存读写、thinking 明细），还会解析 `system` 行里的
API 错误与重试（`api_error`），用于在本轮读数下面提示「这一轮期间有过重试」。

会话日志是**内容块级**落盘，不是逐 token 流式写入，所以：

- 正在流式的数值按块内容估算并标 `≈`，块落盘后自动换成精确的 `usage.output_tokens`；
- 纯解码速度按**每一步内部**的块间隔分别测量再求和（步与步之间夹着的
  工具执行时间不算进去 —— 算进去会把读数压低近十倍）。累加跨度不足 300ms 时
  没有可测区间，那一格显示 `—`，不报假数字；
- **分子分母同源**：块是生成完才落盘的，所以「首块→末块」跨度**不覆盖首块自己的
  生成时间**，它的 token 也就不计入分子（按字符权重摊分）。否则读数虚高一个数量级 ——
  实测某步 13.9s 生成 5904 字符的 thinking，旧口径报 2314 tok/s，同源后是 195；
- `≈` 只标在**具体用了估算的那个数**前面。一轮里 usage 只落在少数步上
  （该 provider 的常态）。**步数不带 `≈`** —— 它数的是 `message.id` 个数；

## 一轮 vs 一步

这两个词在插件里是固定含义：

- **一轮** = 你按下回车 → 这次回复结束。三个读数都在这一整轮上算。
- **一步** = 轮内的一次模型生成（一次 API 调用）**及其触发的工具执行**。轮内的步数
  就是轮内的 API 调用次数 —— 它是第一格读数。

只有「每秒输出」会下沉到步这一层：按每一步内部的块间隔分别测量再求和，
才能把步之间夹着的工具执行时间剔出去。
